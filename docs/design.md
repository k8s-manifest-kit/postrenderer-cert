# Certificate Post-Renderer Design

## Pipeline position

The package implements the existing `types.PostRenderer` contract. It runs on
the final aggregated object batch, after filters and per-object transformers.
Generated cert-manager resources are appended to the batch and can be handled
by later post-renderers.

Missing target objects are ignored because filtering may intentionally remove a
Service, webhook, or workload. Configuration conflicts on objects that are
present are errors.

## Package layout

The root `pkg` package owns the public post-renderer API and pipeline
orchestration. Provider-specific behavior is behind the `provider.Provider`
contract:

- `pkg/provider` contains the shared provider contract, target configuration,
  validation errors, and provider-neutral manifest helpers;
- `pkg/provider/openshift` implements OpenShift Service CA configuration;
- `pkg/provider/certmanager` implements cert-manager Certificate and cainjector
  configuration;
- `pkg/workload_patcher.go` handles provider-neutral workload Secret mounts.

The provider interface is internal to this module's construction path; callers
select the built-in implementations through `ProviderOpenShift` or
`ProviderCertManager`.

## Providers

OpenShift targets receive the Service CA annotations:

- `service.beta.openshift.io/serving-cert-secret-name` on the Service;
- `service.beta.openshift.io/inject-cabundle=true` on webhook configurations.

cert-manager targets receive `cert-manager.io/inject-ca-from` on webhook
configurations. The source may reference an existing Certificate or a
Certificate generated by this post-renderer.

Generated Certificates use the target Service namespace, the configured Secret
name, the configured issuer reference, and Service-derived DNS names. The
Secret itself remains owned and renewed by cert-manager.

When dependency ordering is required, register `engine/pkg/postrenderer.ApplyOrder`
after this post-renderer so generated Certificate objects participate in the
final ordering pass.

## Workload patching

An optional metadata label selector finds workloads in the Service namespace.
The default kinds are Deployment, StatefulSet, and DaemonSet. Matching pod
templates receive a read-only Secret volume and mount. The default volume name
is `webhook-tls` and the default mount path is `/tls`.

An optional container-name predicate selects containers. If it is absent or
matches no containers, all regular and init containers are patched.

## Validation

The post-renderer is idempotent. Existing matching annotations, volumes,
mounts, and generated Certificates are accepted. Conflicting values fail.
Webhook configuration annotations apply to the entire configuration; entries
using different Services are rejected.
